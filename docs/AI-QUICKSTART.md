# 通过 AI 对话使用 EasyBR：接入、操作与排障

[返回项目主页](../README.md) · [任务指令库](AI-PROMPTS.md) · [Windows / Mac 官网教程](https://www.ebrower.com/helperdoc/ai-agent-workflow.html)

EasyBR 提供独立浏览器环境，Easy WebBridge 连接环境中的真实网页，AI Agent 负责理解任务、调用工具和核对结果。你可以从一句任务描述开始，逐步完成环境准备、网页登录、资料处理和问题排查。

本指南适用于 **Windows 与 Apple 芯片 Mac**。账号、环境管理、WebBridge 和网页任务使用同一套流程；首次安装、文件路径和系统权限按所用系统处理。

## 使用前需要准备什么

- Windows 或 Apple 芯片 Mac 上的正式 EasyBR 客户端。
- EasyBR 账号：已有账号就登录，没有账号通过邮箱注册并接收验证码。
- 能运行本机工具的 AI Agent。它需要读取 Skill、运行命令或访问本机 HTTP；纯聊天窗口没有这些能力时不能直接控制电脑。
- 目标网站的合法使用权限，以及任务需要的账号、文件和资料。

EasyBR 1.7.8 及以后内置 Bridge 和扩展，启动环境时自动加载。普通 Chrome、Edge、QQ 浏览器需按[WebBridge 教程](https://www.ebrower.com/helperdoc/easy-webbridge.html)单独安装。目标环境是否可操作，以连接列表和实际命令结果为准。

## 第一步：让 Agent 检查接入

Mac 可安装本仓库的 [easybr-agent Skill](../skills/easybr-agent/)，或下载 [Skill ZIP](../downloads/easybr-agent.zip)。完整 Skill 文件夹放进兼容 Agent 的技能目录；Codex 通常使用 `~/.codex/skills/`。运行本 Skill 的辅助脚本要求 Node.js 20 或更新版本。

把下面的任务交给 Agent：

```text
先识别这台电脑是 Windows 还是 Mac，检查 EasyBR 是否已安装、客户端版本、登录状态、环境列表和内置 Bridge。先报告哪一层已就绪，再处理缺失部分。需要下载时选择对应系统的官方正式安装包；有账号就登录，没有账号时引导邮箱注册和验证码。已安装的环境通过 Local API 和 Easy WebBridge 接入；Mac 首次接入可使用 easybr-agent Skill。保留现有环境。
```

客户端未安装时，Mac Skill 可以辅助下载、核对和安装；需要系统权限时由用户完成。Windows 用户先从[官网下载中心](https://www.ebrower.com/down.html)安装对应版本，再接入 WebBridge。邮箱验证码、密码和设备验证只用于当次登录，不保存到任务文档、脚本或公开资料。

## 第二步：选定已有环境或创建独立环境

```text
列出 EasyBR 环境的名称、ID、启动和 Bridge 状态。使用我选定的环境；若本次任务需要新环境，按我指定的名称新建，保存后核对返回 ID。保留原环境、代理和已有数据。
```

同名环境不应随意取第一个，Agent 应核对准确 ID。新建失败先看套餐、登录和服务端业务错误；超时先重新查询环境列表，不能直接再创建一次。

Mac Skill 默认创建固定环境以保留会话。需要随机生成指纹、配置代理或调整浏览器参数时，在当前客户端设置中操作指定环境，并按要求重新打开使其生效。修改已有环境应先读取完整配置，保留未涉及的字段。

## 第三步：确认 WebBridge 接通

Agent 应核对：环境已经启动、扩展加载在这个环境中、Bridge 连接列表存在对应的浏览器身份。正常的内置扩展不需要重复安装，也不需要启动第二个 Bridge。

| 层次 | 负责什么 | 典型检查 |
| --- | --- | --- |
| 客户端与账号 | EasyBR 是否运行、登录是否有效 | 客户端版本、登录状态 |
| 环境管理 | 选择、创建和启动环境 | 准确环境 ID、运行状态 |
| Bridge 与扩展 | Agent 与目标浏览器的连接 | 在线浏览器身份、能力信息 |
| 网站页面 | 当前页面、账号和任务结果 | URL、页面结构、上传或提交状态 |

环境管理使用 [Local API](https://www.ebrower.com/helperdoc/apidoc.html)，网页操作使用 [Easy WebBridge](https://www.ebrower.com/helperdoc/easy-webbridge.html)。不需要把 API 文档中的每个字段都填进普通任务指令。

## 第四步：按任务操作网页

先告诉 Agent 目标、环境、输入资料、允许的动作和期望结果。Agent 应在指定环境创建任务标签组、复用组内页面，并在导航或页面变化后重新读取结构。

例如：

```text
在我选定的 EasyBR 环境中，打开指定后台，核对当前账号。按我提供的文字和本地文件准备一份草稿，检查上传已完成，回读标题和正文，并提供预览截图。任务结束清理本次创建的临时标签，保留草稿页面与原有标签。
```

如果你授权完整的提交或发布任务，应明确账号、对象、内容和范围。Agent 可以完成任务内必要步骤，不必逐按钮询问；遇到范围不清或必须由你完成的安全验证时再停下。

## 第五步：用结果确认完成

| 动作 | 完成依据 |
| --- | --- |
| 打开网页 | 最终地址、标题和实际内容正确 |
| 填写表单 | 页面显示的字段与给定资料一致 |
| 上传文件 | 网站显示已上传或处理完成，而不只是已选择文件 |
| 下载文件 | 实际文件已落盘，文件名、大小和内容符合要求 |
| 保存或发布 | 回读草稿、记录或发布页面的最终状态 |
| 截图或 PDF | 输出文件存在，内容对应目标页面 |
| 多环境任务 | 按环境和账号分别列出结果，不能混在一起 |

需要持续使用时，正常退出后再打开原环境，核对登录和页面数据是否保留，并重新发现当前标签 ID。定时重复执行由 Agent 或外部任务调度器负责，不能把一次成功当成永久稳定运行。

## 连接不上时怎样排查

先保留原始错误和当前环境，再按层检查：

1. **管理端不可用**：确认 EasyBR 已启动及本机管理接口可访问。
2. **登录失效或未知**：查看实际客户端状态与网络；未知不等于已退出，也不能沿用旧用户名。
3. **环境启动失败**：读取客户端具体错误，检查所选内核、代理、网络和相关设置。
4. **窗口已开但 Bridge 离线**：核对准确环境、扩展加载和本机 Bridge，不反复关开其他环境。
5. **Agent 进程连接失败**：保留连接原始错误；系统的 `Operation not permitted`、连接拒绝、超时和认证失败含义不同。窗口或扩展显示在线不能证明当前 Agent 已有访问权限。
6. **网页任务失败**：检查最新页面结构、当前登录、iframe 与扩展能力；提交状态未知时先查状态，避免重复提交。

```text
排查 EasyBR 操作失败。分别检查客户端与账号、环境启动、Bridge 与扩展、当前 Agent 的本机访问，以及网站页面。保留原始错误，说明失败在哪一层；只处理这次任务涉及的设置，处理后回到失败步骤复测，不清空原环境或反复重启。
```

补充表格见 [Skill 排障说明](../skills/easybr-agent/references/troubleshooting.md)。必须修改产品代码或由网站处理的问题，应明确记录为阻塞，不把“已记录”写成“已解决”。

## 常见问题

**能使用哪些 AI 工具？**
能读取标准 Skill 并访问本机工具的 Agent 可按接口接入。实际能力以你使用的工具、权限和运行环境为准。浏览器里不自带一个可替代所有 Agent 的通用大模型。

**每个环境都要安装一次扩展吗？**
新版 EasyBR 随环境自动加载内置扩展。手动加载普通浏览器或旧版环境时，每个目标 Profile 都要单独检查。

**指纹隔离能保证第三方账号不受限制吗？**
不能据此作出保证。账号状态、网络、业务操作和网站规则等因素仍由网站判断，环境配置不代替账号申诉或安全验证。

**能把后台任务做成专用 Skill 吗？**
可以把稳定流程的输入、目标账号选择、工具调用、结果核对与失败恢复整理成业务 Skill，通过 WebBridge 复用连接。针对内容、CRM、店铺和开发者后台，应分别维护各自的流程。
