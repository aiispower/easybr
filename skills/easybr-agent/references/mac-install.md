# Mac 下载、安装与登录

只适用于 Mac。当前公开 Mac 包面向 Apple 芯片；先检查 `uname -m`，Intel 机器需核对官网是否提供对应包，不安装 arm64 包后宣称兼容。

## 重新下载

```bash
node scripts/easybr.mjs download --dir '/本次独立下载目录'
```

脚本从 `https://www.ebrower.com/comapi/update/getInstaller?osInfo=macos` 获取版本、下载地址、SHA256和大小，实际完整下载并校验。主源失败时仅使用官网 `back=1` 返回且版本、大小和哈希一致的备用；不猜地址、不使用旧版本硬编码链接。目标文件已存在时停止，改用本次新目录；不覆盖既有下载。下载成功只代表文件已核验，尚未安装。

## 解压与核验

先列出 ZIP 内容，拒绝含绝对路径或 `..` 越界路径的包；解压到新目录。实际 Mac 包结构是 `mac-installer/` 下的安装 DMG，名称随版本变化。仅挂载该 DMG，查找其中实际 `.app`：

```bash
hdiutil attach -readonly -nobrowse '/实际下载解压得到的安装包.dmg'
node scripts/easybr.mjs verify-app --app '/Volumes/实际挂载卷/实际应用.app'
```

`verify-app` 必须同时通过 `codesign --verify --deep --strict` 和 `spctl --assess --type execute`。若校验失败，停止安装并记录原始诊断；不删除 quarantine、不关闭 Gatekeeper、不运行包中的卸载或修复脚本来绕过验证。

## 实际替换安装

1. 记录已有环境身份、配置摘要和运行状态。备份记录只留本机私有目录，不输出 Cookie、账号凭据或完整配置。
2. 正常退出需要关闭的浏览器环境与 EasyBR 管理端，确认相关进程已退出。用户要求不强杀时不调用有强制结束兜底的环境关闭 API，不发送 SIGKILL。
3. 用户数据目录保持原样；不要运行 `uninstall-easybr.command`、不要清理环境缓存或数据库。已有应用先移到本次本机备份目录，再用 Finder 或 `ditto` 将核验过的 `.app` 实际复制到 `/Applications/`。需要系统权限时让用户完成。
4. 核对已安装应用的版本和签名后，从这个准确的 `/Applications/...app` 路径启动，不启动 DMG 内应用或旧备份。安装失败时恢复刚才的应用备份，不覆盖用户数据。
5. 卸载 DMG；保存本次包的版本、大小、SHA256、签名检查、安装路径和启动证据。重新下载和实际替换安装都成功，才记为“重装完成”。

## 登录、注册与后续

已有账号在现有登录界面直接登录。没有账号时进入客户端现有注册界面，填写用户选择的邮箱，点击获取验证码；由用户在收件箱或垃圾邮件中查收并填写，或者将验证码提供给 Agent 仅用于当前注册。密码设置、协议确认由用户按页面完成，注册成功后再登录。

邮箱验证码失效时重新获取并使用最新一封；提示邮箱已注册时返回登录或找回密码。登录失败不能作为另注册账号的理由。邮箱验证码与图形 CAPTCHA 不同，可以辅助填写用户主动提供的邮件验证码，不尝试绕过图形 CAPTCHA 或账号安全验证。不声明自动读取用户邮箱，不保存账号密码和验证码，不把它们写入脚本、命令参数、配置、教程、截图或日志。

用户要求完整登录验收时，即使重装保留会话，也要在授权范围内正常退出登录再登录一次。成功证据是客户端登录后回到环境列表，且当前账号一致；再运行 `doctor`、`list` 辅助确认。新版状态接口会核对实际界面会话与服务端账号，`doctor` 的 `api_login_verified: true` 和 `username` 可用于日常账号确认，无须每次退出重登。旧客户端只返回服务在线，或 `login_status: unknown` 时，需要检查实际界面；列表成功不能代替账号确认。`ui_login_verified: false` 表示这个只读命令本身没有执行界面重登验收，不能把 API 查询描述成已实际完成重登。

下载/安装包不包含用户已有环境数据；保留用户数据重装后应核对环境仍存在。然后新建独立测试环境，原有环境不用于上传、下载和网页填写验收。
