# 分层排障

| 现象 | 先确认 | 处理与复测 |
| --- | --- | --- |
| 下载源失败 | 官网元数据可用，版本/哈希/大小齐全 | 用同版本且哈希一致的官网备用源；完整下载重新校验 |
| 签名或 Gatekeeper 不通过 | 下载 SHA256、实际 `.app` 路径、校验原始输出 | 停止安装，记录问题；不运行卸载/修复脚本，不关闭系统验证 |
| 管理端不可用 | 安装路径、客户端是否运行、端口是否被占用 | 启动准确应用；不杀占用端口的未知程序；`doctor` 复测 |
| 管理端在线但未登录 | `doctor` 的 `login_status` | `logged_out` 时在客户端登录；没有账号才引导邮箱注册；登录错误不擅自另注册 |
| 无法确认当前账号 | `login_status: unknown`、客户端版本、网络和实际界面 | 旧版可升级后重新诊断；网络恢复后再查询，不沿用旧用户名或凭列表成功推断登录 |
| 已确认登录但环境列表失败 | 当前用户名、账号访问权限、网络、套餐 | 核对目标账号并处理实际错误，再运行 `list`；不重复注册 |
| 新用户没有账号 | 用户邮箱和现有注册界面 | 引导获取邮箱验证码，在收件箱或垃圾邮件查收；用户完成密码设置和协议确认，注册后登录 |
| 邮箱验证码未收到或失效 | 邮箱拼写、垃圾邮件、页面发送提示 | 按页面提示重新获取并使用最新一封；仅辅助填写用户提供的验证码，不读取邮箱或保存验证码 |
| 注册提示邮箱已注册 | 当前邮箱和页面提示 | 回登录或找回密码，不重复注册 |
| 新建超时 | 精确名称是否已出现，客户端提示 | 先查列表，回执不明不重复创建；记录返回的真实ID |
| 环境无法启动 | 登录/额度、内核是否下载、磁盘、代理配置 | 按客户端实际提示处理；不自动修改原有环境或切换账号 |
| 内核下载失败 | 客户端版本、系统/架构、所选内核、下载阶段（元数据、传输、解压/校验/安装） | 对照客户端实际状态区分“下载地址/元数据失败”“网络传输失败”“解压/校验失败”和“安装替换失败”。请求官方元数据时由客户端按平台与内核号选择；使用官方提供的版本、SHA256、大小与地址，不从旧教程或搜索结果拼链接。海外可用官方 GitHub 源，国内用官网当前指定源；如账号已购 OSS 只用客户端/官网给出的地址。更换来源必须保持同一版本与哈希，下载后重验。不要删除内核目录或用户数据。 |
| 内核目录 EPERM / 替换失败 | 目标内核是否正在运行、目标目录权限、错误阶段、备份目录是否生成 | 这是下载后安装/替换阶段，不等同于网络下载失败。不要反复删除目标目录、不要清用户数据、不要手工覆盖；先保留日志和备份状态，按客户端提示关闭使用该内核的环境并复测。若已有版本仍可用，先确认其启动文件与版本，再由客户端安全更新流程处理。 |
| 环境启动报错 | 准确环境 ID、本机内核路径/可执行文件、磁盘、端口、代理连通、账号额度 | 记录完整错误和时间，逐项核对路径存在性与权限、端口占用来源、代理配置/凭证是否可用及套餐额度。不要杀未知进程、复制其他环境凭证或删目录。 |
| 已打开但 Bridge 不在线 | `doctor`、准确环境的扩展、实际扩展版本与能力 | 等待连接，检查扩展；不反复关闭重开，必要时在该测试环境补装官方扩展 |
| Bridge 健康但认证失败 | 本机 Token 文件和运行服务是否一致 | 只核对存在性和权限，不打印 Token，不替换其他任务服务 |
| 同名环境多条 | 返回的准确ID和用户业务绑定 | 明确目标ID，禁止取第一个或模糊命中 |
| 更换磁盘或电脑迁移 | 同机换盘还是异机、所选数据范围、备份范围、环境数据位置、目标空间/权限 | 同机换盘逐项核对原数据目录与新路径并先备份；异机先比较客户端的云同步/恢复能力与离线迁移教程，再选路径。Cookie、LocalStorage、IndexedDB、SessionStorage 等是否迁移取决于选项、客户端版本和目标系统；云快照与本地迁移不可默认视为等价或覆盖相同范围。先备份并用非关键站点验证；跨设备加密/钥匙串条件不同可能无法恢复登录，当前不承诺登录态无损。失败时保留源副本，停止覆盖，核对错误阶段后从备份恢复。 |
| 页面控制失败 | 精确browserId、tabId、当前快照、iframe和扩展能力 | 更新快照后有限重试只读步骤；核对页面最终状态，勿重复提交 |
| 关闭可能强杀 | 用户是否要求正常退出 | 正常退出浏览器；未允许客户端强制兜底时不调用 close API |

记录每个问题的触发条件、实际错误、影响、处理、复测结果。邮箱验证码可由用户填写或提供给 Agent 仅用于当前注册；不要将其误作图形 CAPTCHA 而停止辅助填码。图形 CAPTCHA 和账号安全验证由用户完成；有具体阻塞时保留当前任务状态并说明继续条件。若必须改 Electron/后端/内核才能处理，报告为未完成项，不擅自扩大本轮范围。

## 内核元数据和下载来源

客户端通过现有 `GET /update/getfilenew` 流程请求内核元数据，携带所选内核号、客户端版本、平台等信息；响应经下载配置后可包含版本、当前选用的 `loadurl`，以及可选的 `sha256`、`size`。需要备用源时由客户端用官方 `back` 请求参数重新请求元数据，并使用该响应返回的 `loadurl`；不要假设元数据固定带有 `backupUrl` 字段。具体支持平台、内核和版本以当前客户端提供的元数据为准，不把某个文档中的旧版本号当作最新版本。不要手工构造接口 URL 或从搜索结果猜测 CDN/GitHub 地址。

先确认失败发生在元数据请求、下载传输、解压/校验、安装替换还是浏览器启动阶段。只有传输失败才考虑通过客户端官方 `back` 请求参数重新获取源地址；海外官方 GitHub 源、国内官网官方源及账号已购 OSS 都必须由当前客户端/官网返回 `loadurl`，不可猜测地址。切换来源后版本和 SHA256 必须与所选元数据一致；有大小字段时也核对文件大小。校验不符就停止，不要安装。

## 指纹与环境设置边界

指纹选项取决于系统、内核版本、客户端版本和当前 UI 能力；只解释 UI 实际出现且可保存的字段，不承诺每个网站检测结果或浏览器 API 均能伪装。新环境设置通过现有界面/API 的 `browserOptions` 对象表达；旧客户端可能不识别该字段。仅在客户端能力信息或当前界面确认支持后使用新选项；缺字段时保留旧环境既有值，不用默认值覆盖，不虚构字段名。

## 窗口排列

新版管理界面支持宫格和对角线排列、选择显示器、正序/倒序，以及可为负的间距或偏移。宫格默认间距为 -20；对角线默认步长为 20。例：窗口宽 500、水平间距 -400 时横向步长是 100。先核对目标窗口与显示器；点击“开始排列”后才保存本次设置，关闭或取消对话框不会保存未提交的修改。之后可再次打开继续调整。旧客户端没有该界面时，不按新版步骤引导。
